Design goals

Build the website first

Content can grow over time; the foundation should already be clear, consistent, and reliable.

Low dependency

Static core

The main pages run without a build tool. Structure, styling, and behavior remain easy to maintain and move.

Extensible

Content separated from interface

Projects, study, results, and life share consistent content patterns, so new material does not require a redesign.

Core features

Designed around reading and access

Each feature helps visitors locate pages, choose a reading environment, or complete an interaction.

Navigation

Multi-page, bilingual, searchable

Global navigation, section navigation, current-location highlighting, and keyboard search support different paths through the site.

Reading

Themes, responsive layout, and tools

System-aware light and dark modes work across desktop, tablet, mobile, and printed output.

Interaction

Weather and public messages

Weather requests location only when needed; the guestbook supports publishing, display, and protected administration.

Implementation

From structure to delivery

Responsibilities stay separate: HTML carries meaning, CSS controls the visual system, JavaScript enhances behavior, and external services provide only necessary data.

HTML

Semantic multi-page structure

Chinese and English pages correspond directly, with clear heading levels, anchors, fallback routes, and search metadata.

CSS

Shared tokens and breakpoints

Color, type, spacing, radius, and grid rules are centralized and shared by both themes and every screen size.

JavaScript

Progressive enhancement

Menus, search, section tracking, reading mode, and motion build on readable pages while respecting keyboard and reduced-motion use.

Services

GitHub Pages and Supabase

GitHub Pages serves static assets; Supabase handles messages and administrator verification without exposing private credentials in the frontend.
